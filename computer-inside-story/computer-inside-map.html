The one big idea

When you run code, instructions and data move through layers. Your program asks for something. The runtime and operating system prepare it. The CPU works on it. Caches and RAM supply data. Devices show the result.

Never mix these two questions:
“Where is the data logically?” means virtual memory. “Where is it physically?” means a real cache or DRAM location.

Important terms — simple but correct

UEFI / firmware / flash memoryUEFI is the startup program. It lives in flash memory on the motherboard, so it stays when power is off. “ROM” is the old general word people often use.
OS loaderThe operating system component that creates a process and maps its program file, libraries, stack, and heap into virtual memory.
Virtual addressThe address the program uses. It is private to that process; it is not a literal RAM-chip location.
MMU + page tableThe MMU is CPU hardware that translates virtual addresses. The OS creates page tables that tell it which physical RAM frame is allowed.
TLBA tiny, fast cache of recent virtual-to-physical translations. It avoids checking page tables for every access.
Physical addressThe location after translation. The memory system uses it to find cache lines or a DRAM location.
SRAM cacheVery fast memory on or near the CPU: L1, L2, and often L3. It holds copies of recently used data and instructions.
DRAM (main RAM)Large, cheaper, slower memory in RAM DIMMs. It stores pages while programs are running and must be refreshed.
RegistersThe smallest, fastest storage inside a CPU core: instruction pointer, addresses, numbers, and results live here briefly.
SSD / NAND flashPermanent storage for programs and files. It is far slower than RAM but remembers when power is off.

Why cache comes before RAM

The CPU checks L1 → L2 → L3 before DRAM. A cache hit is quick; a cache miss asks the next level. This is why code with nearby, reused data often runs faster.

Why a variable may have no RAM address

An optimizing compiler can hold a number only in a register, combine it with another value, or remove it completely when its answer is already known.

What a page fault means

If a valid virtual page is not in RAM, the CPU traps to the OS. The OS brings it from the program file or swap, updates the page table, then restarts the instruction.

What happens at the screen

Console output usually passes through a runtime buffer and a system call. Graphics normally go through a window system and GPU driver. The OS controls safe device access.

Advanced truth: the diagram is simplified on purpose

Modern cores decode instructions into micro-operations, execute independent work out of order, speculate on branches, and retire results in order. Physical addresses may pass through coherent cache hierarchies, memory controllers, channels, ranks, banks, rows, and columns. The diagram is a correct foundation, not every transistor-level event.
