A professor’s mental model

Do not mix the layers

Every time you learn a step, first ask: which layer is doing the work? This prevents common confusion, such as saying “the CPU runs my JavaScript” without explaining the JavaScript engine in between.

1. Your programYour variables, functions, and instructions.
2. Runtime / compilerTurns language ideas into machine work.
3. Operating systemShares CPU, memory, files, and devices safely.
4. HardwareCPU, cache, RAM, SSD, and screen do physical work.

Use these four questions on every chapter:

① What data is moving?② Where is it stored now?③ Who is in control?④ What changes next?

First important correction: there are two stories

Story A — boot: power button → firmware → operating system. This only happens after the computer was off. Story B — launch: clicking Run while the OS is already awake → a new process → CPU executes it. Most of the time, you are doing Story B.

All languages meet at the same hardware, but take different routes first:

C / C++ / Rust / Gocompiler → native machine instructions → OS loader
Java / C#bytecode → VM → JIT compiler → native instructions
JavaScriptsource → JS engine → interpreter/JIT → native instructions
Python (CPython)source → bytecode → interpreter; the interpreter itself is native code

Precision note: a variable may stay only in a register; a page table maps a virtual page to a physical RAM frame; and many CPUs check a TLB and L1 cache partly in parallel. The diagrams show the required ideas, not one exact wiring order for every CPU.
